# 企業と締切タスクを同じトランザクションで保存する

- 決定日 2026-11-21（JST）
- 作業担当 Codex
- 対象 Issue #28、PR #65

## 背景

企業フォームで締切を同時に保存する場合、企業の更新が成功した後でタスクの保存が失敗すると、入力の一部だけが残る。別の操作が企業を更新してから補償処理が走ると、その更新まで上書きする可能性がある。

## 決定

締切を含む送信では、Supabase の Postgres 関数で企業とタスクを同じトランザクションに保存する。関数は認証済みユーザーの権限で実行し、既存の所有者・ワークスペース制約と RLS を適用する。更新時は表示時の更新日時を照合する。

企業フォームで編集する締切は、同じワークスペースにある期日付きの未完了タスクのうち、期日が最も早い1件とする。期日が同じ場合は ID の昇順で選ぶ。既存の進行状態を維持し、締切欄が空ならタスクを書き換えない。

## 影響範囲

企業登録・編集の締切入力とダッシュボードの締切表示に関係する。対象環境では締切付き保存を使う前に `202611210001_company_deadline_atomic_rpc.sql` を適用する。
