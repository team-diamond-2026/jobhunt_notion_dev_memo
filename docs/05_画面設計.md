#### MVP実装（Issue #8）

- `/interviews`: 面接日が新しい順の一覧。企業で絞り込み、次回までにやることを確認できる。
- `/interviews/new`: 新規記録。`company_id` クエリがある場合は本人の企業であることを確認して初期選択する。
- `/interviews/[id]`: 企業・面接日・形式・質問内容・回答内容・振り返りと改善点・次回の行動を表示する。
- `/interviews/[id]/edit`: 保存済みの内容を読み込んで編集する。保存後は詳細へ戻る。
- `/companies/[id]`: 企業基本情報と、その企業の面接ログを表示する。企業を選択した状態で新規記録へ進める。
- ホーム・企業一覧から面接ログへ遷移できる。企業一覧の企業名から企業詳細へ進める。
- 企業未登録時は企業登録を案内し、記録がない場合は最初の記録作成へ誘導する。
- 企業・面接日・形式を必須とし、振り返りは後から追記できる。質問と回答は同じ順で改行して記録する。
- 入力エラーを項目に紐付け、保存中は入力と再送信を止める。保存失敗時は入力を保持して再試行できる。
- スマホでは縦1列に配置し、入力文字は16px、操作対象は高さ44px以上とする。長い企業名や改行を含む記録は折り返す。
- 未ログイン時はログインへ遷移し、他人のログ・企業や不正なIDは404にする。取得失敗は空データと区別して再試行を案内する。

- Notion風の余白とシンプルなUIを意識する


## 実装済みUIの統一（Issue #49）

- 共通ヘッダー、ページ見出し、カード、主操作・補助操作・削除ボタン、入力欄、結果メッセージの見た目を統一する。
- ライト・ダーク・システム設定に応じて背景、文字、境界線、状態表示の色を切り替える。
- 主要な操作対象と入力欄の高さは44px以上。スマホの入力文字は16pxとし、長い企業名・メールアドレス・メモを折り返す。
- 企業登録フォームは「企業を追加」から開閉する。検索欄が長い登録フォームで隠れないようにする。
- 企業検索は企業名・業界・選考状況・並び順を明示し、検索条件のクリア操作をまとめて配置する。検索後も条件を保持する。
- 企業カードには選考状況、企業名、業界、志望度、メモ、更新日、詳細・編集・削除の操作をまとめる。
- 未登録と検索結果0件を区別し、登録方法または条件クリアへの導線を案内する。ESの空表示でも絞り込み状態を区別する。
- 企業登録中はフォームを操作できない状態にする。失敗時は入力を保持して再試行を案内し、成功時は通知して入力を初期化する。
- 取得失敗は空データとして扱わず、内部エラーを表示しないエラー画面から再読み込みできるようにする。「もう一度読み込む」は同じ `startTransition` 内で `router.refresh()` と `reset()` を呼び、Server Componentのデータを再取得する。失敗が続く場合はエラー案内から再試行できる。
- 選考ボードの横スクロールはボード内に限定し、キーボードでも操作できる領域にする。
- キーボードのフォーカス表示、本文へ移動するリンク、入力ラベル、通知の `status` / `alert` を用意する。

### 検証

`app/` で `npm ci` 後、以下を実行する。

- `npm test`: 企業登録の必須入力・二重送信防止・成功・失敗後の再試行、検索0件と未登録、検索条件の保持、エラーの再読み込み、未認証、ナビゲーションの現在地を検証する。
- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`（既存のSupabase環境変数が必要）

取得失敗からの復帰は、実際のNext.jsエラー境界と、再取得時に企業一覧のServer Componentを実行するルーターのテスト用アダプターで検証する。DBアダプターを失敗から成功へ切り替え、「もう一度読み込む」だけで取得が再実行され、検索条件を保ったまま企業一覧を表示することを確認する。失敗継続時のエラー案内と、その後の再試行による復帰も検証する。実ブラウザ・実Supabaseでの検証は別途必要。

実画面では320 / 375 / 768 / 1280px幅、ライト・ダーク・システム設定、長い企業名・メールアドレス、0件・取得失敗・登録失敗を確認する。ページ全体の横スクロールがなく、Tabキーで検索・登録・ナビゲーション・ボードへ移動できることを確認する。
