## UI方針
- 共通ヘッダーからダッシュボード・企業一覧・選考ボード・ES管理・設定へ遷移
- 中央にメインコンテンツ
- モバイルではナビゲーションを折り返し、現在地を色と `aria-current` で表示する
- Notion風の余白とシンプルなUIを意識する


## 実装済みUIの統一（Issue #49）

- 共通ヘッダー、ページ見出し、カード、主操作・補助操作・削除ボタン、入力欄、結果メッセージの見た目を統一する。
- ライト・ダーク・システム設定に応じて背景、文字、境界線、状態表示の色を切り替える。
- 主要な操作対象と入力欄の高さは44px以上。スマホの入力文字は16pxとし、長い企業名・メールアドレス・メモを折り返す。
- 企業登録フォームは「企業を追加」から開閉する。検索欄が長い登録フォームで隠れないようにする。
- 企業検索は企業名・業界・選考状況・並び順を明示し、検索条件のクリア操作をまとめて配置する。検索後も条件を保持する。
- 企業カードには選考状況、企業名、業界、志望度、メモ、更新日、詳細・編集・削除の操作をまとめる。
- 未登録と検索結果0件を区別し、登録方法または条件クリアへの導線を案内する。ESの空表示でも絞り込み状態を区別する。
- 企業登録中はフォームを操作できない状態にする。失敗時は入力を保持して再試行を案内し、成功時は通知して入力を初期化する。
- 取得失敗は空データとして扱わず、内部エラーを表示しないエラー画面から再読み込みできるようにする。
- 選考ボードの横スクロールはボード内に限定し、キーボードでも操作できる領域にする。
- キーボードのフォーカス表示、本文へ移動するリンク、入力ラベル、通知の `status` / `alert` を用意する。

### 検証

`app/` で `npm ci` 後、以下を実行する。

- `npm test`: 企業登録の必須入力・二重送信防止・成功・失敗後の再試行、検索0件と未登録、検索条件の保持、エラーの再読み込み、未認証、ナビゲーションの現在地を検証する。
- `npm run lint`
- `npm run build`（既存のSupabase環境変数が必要）

実画面では320 / 375 / 768 / 1280px幅、ライト・ダーク・システム設定、長い企業名・メールアドレス、0件・取得失敗・登録失敗を確認する。ページ全体の横スクロールがなく、Tabキーで検索・登録・ナビゲーション・ボードへ移動できることを確認する。
