# 13 カレンダー・タスク連携方針

## 対象

Issue #38「ダッシュボード・タスク連携とモバイル確認」で採用するMVP方針を記録する。

## 直近予定の表示

- 予定の取得元は `events` テーブルに統一する。
- ダッシュボードの「直近の予定」では、現在時刻以上・7日後の同時刻未満のイベントを開始日時順で最大5件表示する。6件目以降は「カレンダー」から確認する。開始済みの予定はこの枠には表示しない。
- カレンダーでは月表示と週表示を切り替え、イベントを選ぶと開始・終了日時を確認できる。
- 日付の表示と月/週の期間判定は `Asia/Tokyo` を基準にする。週は日曜0時以上・次の日曜0時未満。月グリッドは前後月の補助日も取得し、スマホの月一覧には対象月だけを表示する。
- 複数日にまたがる予定は、表示期間と重なる日にも表示する。終了日時は排他的で、0時に終了する場合は翌日に重複表示しない。ダッシュボードは開始日時基準なので、開始済みの継続中イベントはカレンダーで確認する。
- ダッシュボードから予定を選ぶと、その開始日を含む週表示の詳細へ移動する。月/週の切替でも選択中の予定と日付を維持する。
- イベント作成・編集は Issue #37 の対象とし、このIssueでは保存済みイベントの読み取りと導線を扱う。
- 作成・編集・削除後は `/` と `/calendar` のキャッシュを無効化し、次の表示で両画面に反映する。別端末での変更は再読み込みで反映する（リアルタイム同期は範囲外）。

### #28「今日の予定・今週締切」との境界

両画面のイベント取得列は `CALENDAR_EVENT_COLUMNS` を共有する。ダッシュボードは `events.start_at`、カレンダーは開始・終了と表示期間の重なりを対象にする。#38の「次の7日間」はローリング期間であり、#28の「今日」「今週」と同じ範囲ではない。

| 表示枠 | 取得元 | 期間・扱い |
| --- | --- | --- |
| #38 直近の予定 | `events` | 現在時刻以上・7日後未満、開始順で最大5件 |
| #28 今日の予定（追跡先） | 同じ `events` | JSTの今日0時以上・翌日0時未満。開始済みも含めて「今日」を表す |
| #28 今週締切（追跡先） | #20で保存される `tasks.due_date` と状態 | JSTの日曜0時以上・翌日曜0時未満、未完了だけ。#20の日時型・状態仕様が確定してから実装する |

#28のウィジェットをこのIssueで完成扱いにはしない。取得元・タイムゾーン・週境界を上記に揃え、期間名の異なる枠を混同しない。`events.event_type=deadline` は手動登録した予定であり、未完了タスク数には数えない。

## タスク期限の扱い

MVPの本Issueでは、`tasks.due_date` をカレンダーへ表示しない。タスク管理はMVPの「あれば強い機能」であり、Issue #20 の作成・更新・完了状態の保存/取得が未実装のためである。

イベントとタスクは次のように区別する。

| 種類 | 用途 | 日時 | 状態 |
| --- | --- | --- | --- |
| イベント | 面接、説明会、提出締切など、その日時に起きる予定 | `events.start_at` / `events.end_at` | イベント種別で分類 |
| タスク | ES作成、面接準備など、完了管理する行動 | `tasks.due_date` | `todo` / `doing` / `done` / `archived` |

追跡先は [Issue #20](https://github.com/team-diamond-2026/jobhunt_notion_dev_memo/issues/20)。延期範囲は、タスク期限のカレンダー取得・描画、完了/アーカイブ時の非表示、および実データでの結合確認である。#20で対応するときは次を受け入れ条件として引き継ぐ。

- 期限ありの `todo` / `doing` のみ表示し、`done` / `archived` と期限なしを除外する（状態名は#20の確定仕様と合わせる）。
- タスクからイベントを複製せず、`events` と未完了の `tasks` を別ソースとして統合する。表示上も「予定」「タスク期限」を区別する。
- 識別子を `event:<id>` / `task:<id>` に分け、同一レコードの二重表示を防ぐ。手動で同名のイベントを登録した場合は別レコードとして扱い、タイトルや時刻の一致だけでは自動削除・統合しない。
- 保存→月/週表示→完了→再表示を実際のタスクデータで確認する。#38のイベント検証でタスク連携まで確認済みとは扱わない。

## モバイル表示

- 768px未満では、月表示を横に縮めず、予定がある日だけを日付別リストで表示する。
- 週表示は7日分を縦に並べ、予定がない日も明示する。
- イベントを選ぶと同じ画面内の詳細へ移動し、開始・終了日時を確認できる。
- スマホの予定名・詳細は長い英数字も折り返す。月/週・期間移動・閉じるの操作領域は高さ44px以上を確保する。
- 768px以上では7列のカレンダーグリッドを表示する。

表示だけを確認する場合は `CALENDAR_PREVIEW=true npm run dev` で起動できる。サンプル日時は今日を基準にし、表示月/週を動かしても移動先に合わせて再生成しない。サンプル表示であることを明示し、作成・編集リンクは出さない。このモードは開発環境限定で、本番ビルドではフラグがあってもログインが必要。プレビューは保存・認証・RLSの検証には使わない。

結合確認の手順・実施環境・結果は [カレンダー結合確認](./16_カレンダー結合確認.md) に記録する。
