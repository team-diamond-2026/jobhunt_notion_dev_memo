| 対象 | 実行した内容 | 結果 |

テストはネットワーク接続・実ユーザーデータ・本番DBへの書込みなしで再実行可能。Supabase管理のauth関数/ロール/権限と通信はテスト用の代替を使う。PGliteではpgcrypto拡張宣言のみ省き、組み込みUUID関数を使用する。実Supabase/Authやブラウザ操作の検証を代替するものではない。

同じ秒内の更新でもDBのupdated_atは進み、表示上はv1/v2/v3で識別できる。通常TZと `TZ=America/Los_Angeles` の両方で9テスト成功。`npm run lint` / `npm run build` も成功。

### 管理者への依頼内容

対象はアプリが接続しているSupabaseプロジェクト。SQL Editorで以下を実施する。

1. [セットアップ手順](../supabase/README.md) と適用済みマイグレーションを照合し、不足分をファイル名順に適用する。特に `202610170001_es_document_versioning.sql` が必要。
2. [ES権限修正SQL](../supabase/migrations/202611140001_es_document_authenticated_access.sql) を適用する。既存の所有者RLSを維持したまま、`authenticated` にESテーブルのSELECT/INSERT/UPDATE/DELETEだけを付与する。RLS/所有者ポリシーが未適用なら例外で停止するので、先に初期スキーマを確認する。
3. [読取り専用確認SQL](../supabase/checks/es_update_status.sql) を実行し、8項目すべてがtrueになることを確認する。falseがあればチェック名のみ共有する（ユーザーデータ・秘密情報は不要）。
4. 適用完了後、アプリでES一覧を再読み込みし、上記の新規作成→編集2回→一覧/詳細/DB照合を実施する。SQLチェックだけでは完了扱いにしない。
