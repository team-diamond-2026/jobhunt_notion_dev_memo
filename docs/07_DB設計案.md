# 07 DB設計案

## 想定テーブル

### users
- id
- name
- email
- created_at

### workspaces
- id
- user_id
- name
- created_at

### companies
- id
- user_id（現行アプリの所有者。RLSでauth.uid()と照合）
- workspace_id
- company_name
- industry
- motivation_level
- selection_status（MVPの現在選考状態の唯一の正本）
- memo
- created_at
- updated_at

### applications
MVPアプリでは使用しない将来用の表。現在状態の二重保存や、変更ごとの履歴行追加は行わない。テーブルが存在しても応募単位・時系列履歴の仕様が実装済みという意味ではない。

- id
- company_id
- status
- applied_at
- created_at
- updated_at

正本・9種類の保存値・既存編集との対応・ボード更新契約は [選考ステータス保存方針（#32）](./21_選考ステータス保存方針.md) を参照。`companies.updated_at` は企業全体の最終更新日時で、選考段階への到達日時ではない。
