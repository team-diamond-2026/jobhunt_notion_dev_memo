## 面接ログのMVP実装（Issue #8）

- `202606270001_mvp_schema_and_rls.sql` の既存 `interview_logs` テーブル、企業経由のRLS、更新日時トリガーを使用する。
- 追加マイグレーション: `supabase/migrations/20261114000000_interview_log_access.sql`。企業・面接日・作成日時のインデックスと入力列の更新権限を追加し、テーブル・既存レコードの型や値は変更しない。
- 所有者は既存の `companies.user_id` を参照し、ワークスペースを含む現行MVPスキーマと併用する。
- `company_id` は必須の外部キー。企業削除時は関連ログも削除する。
- `interview_date` は既存の `timestamptz` を維持する。画面は日付のみ入力し、日本時間の午前0時として保存・日本時間の日付として表示する。
- 新規保存時は企業・面接日・形式をサーバーで検証する。形式は「対面」「オンライン」「電話」「その他」、日付の入力範囲は0001-01-01〜9999-12-31。
- `questions` / `answers` は既存の `jsonb` 配列。画面では改行区切りのテキストに変換し、保存時に各行を文字列配列に戻す。未記入は空配列とする。
- `reflection` / `next_action` は既存のテキスト列。入力欄はいずれも10,000文字以内とし、面接後に追記できる。
- 日時・形式・振り返りがNULLの既存記録も表示できる。面接日未設定の記録は一覧の末尾に表示する。
- `created_at` / `updated_at` はDBが設定し、既存トリガーで `updated_at` を更新する。
- 既存RLSで本人の企業に紐づくログだけを取得・追加・更新でき、他人の企業への付け替えを拒否する。追加の権限設定で匿名ユーザー、システム列の書き換え、ログ削除を制限する。
- サーバー側でも認証・企業所有者・編集対象の所有者を確認する。適用手順と検証方法は `app/README.md` を参照する。
